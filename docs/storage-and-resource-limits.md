# Storage and resource limits

Both apps start with a **500 MB** received-file quota and a **100-file** cap, counting completed copies and receive partials, including empty files. Android Settings → Storage and Mac Settings → General → Storage offer 250/500/1000 MB. Lowering the limit preserves existing files; new offers are rejected until there is enough room. Mac quota checks include the remaining space reserved by other paused receivers. The per-file limit remains 100 MB and each app retains at most one outgoing snapshot. A free-space margin of 8 MB is required for a new receive offer.

Quota/full-disk rejection sends `STORAGE_FULL`, distinct from sharing permission rejection, checksum failure and disconnection. Sending apps explain how to make room. Android also keeps a failed receiving row visible on Home/Files. Resume of an already admitted partial is allowed after lowering the quota. Received data is never automatically removed merely because it exceeds a new limit. Existing data from older builds can exceed the quota; it is retained and blocks new offers until the user makes room.

Android Settings → Storage shows usage and can remove **completed private received copies and their records**, and orphan verified private copies after confirmation. Save As exports in other apps/folders are never targets. Active/paused transfers stay available. Export and explicit cleanup serialize on IO without holding the receiving mutex through a potentially slow document-provider export. Copy cleanup is restricted to generated `.verified` paths inside the private receive directory. An interrupted publication can leave an orphan verified copy; it counts against the quota until explicitly removed with this cleanup action. Clearing records alone never deletes a received copy.

Mac Settings → General → Storage opens Received Files in Finder. Users can move or remove files themselves; MacBridge never automatically deletes these verified files. It stores no clipboard or transfer history. Usage refreshes on storage-sheet/app activation and file offers/completion, not through an idle polling loop. Unsupported/symlink folder entries stop admission rather than following a path outside the receive folder.

Android keeps the latest 100 clipboard entries, 200 finished transfer records without retained files, and 50 notification history records through transactional pruning at insertion and startup. Received-copy records and unfinished transfers are retained for recovery/access. Settings offers clipboard and finished-transfer history clearing. Clipboard content persisted by this flow is limited to 64 KiB UTF-8; incoming Mac clipboard processing uses the same bound. Existing oversized clipboard history is removed on Android startup. The clipboard itself remains an OS-managed surface, independent of history cleanup.

Authenticated traffic uses transport/companion-wide token budgets that survive reconnects within a running process. Each side allows 512 frames/second with a 1024-frame burst, and 16 MiB/second of wire data with a 32 MiB burst. Separate budgets allow clipboard work at 2/second (burst 10), notifications at 30/second (burst 60), notification actions/heartbeats at 10/second (burst 20), and file offers/resume hashing at 1/second (burst 4). File chunks, acknowledgements and cancellation use the general frame/byte budgets. Excess traffic closes the session before further expensive processing. Android stops automatic reconnect for this failure and shows a fixed recovery message; wait for budget refill, then Connect. Restart resets in-memory rate budgets, not disk quotas. These bounds deliberately limit transfer throughput under sustained traffic; they are not an Internet-facing denial-of-service defense or limits against a malicious local administrator.

Valid restart-resume snapshots remain for the existing ten-minute recovery window. Rejection, cancellation, invalid/expired restoration and permission changes release unverified copies; shutdown can preserve a valid resume checkpoint intentionally. Ordinary Unicode transfers, heartbeat, reconnect, cancellation, permission revocation and resume remain covered by the regression suites. Synthetic sparse files model quota exhaustion without modifying live user files; provider fixtures verify exported files survive cleanup. See issue #30 for executed counts and installation results.
