# Same-key Mac certificate renewal

In the installed Mac app, open **Settings → General → Certificate**. The compact row shows the expiry date, warns within 30 days, and identifies expired/not-yet-valid certificates. Click **Renew** to issue a fresh one-year self-signed certificate using the existing private key. Status refreshes on app activation and normal engine events; it does not run an idle redraw timer. Check clocks on both devices if a certificate is not yet valid.

The phone public-key pin, Mac device ID, peer records, Keychain migration account and key remain unchanged. Active sessions/transfers keep their existing TLS context; new connections use the validated renewed context. If a failed connection had already stopped, tap Connect again on the phone. Android Home/Devices and pairing errors give expiry/clock recovery guidance while retaining normal certificate validity and saved-key checks. A fresh pairing code cannot fix expiry and is not the instructed recovery.

Renewal checks the original certificate and private key against the running identity. The private key enters OpenSSL over a private stdin pipe and an unlinked, owner-only temporary descriptor for TLS loading; no durable key export or new key generation occurs. The public certificate candidate is bounded, dated, same-key checked and loaded into a fresh TLS context before an owner-only, flushed candidate atomically replaces the certificate. A changed certificate, stopped process, missing/denied identity, malformed/oversized input, signing/TLS failure or failed replacement cannot silently rotate pairing. If a process is killed around publication, restart loads the complete old or new certificate; it never promotes an abandoned candidate automatically. Public candidate files may remain after forced process termination and can be removed after the app stops. Filesystem power-loss durability is not a universal guarantee.

Use a separate test state directory for expired/future-dated fixtures. Never change machine clocks, revoke a live key or replace the real certificate with a deliberately invalid fixture for tests. Automated checks cover actual expired and future certificates, the 30-day boundary, same-key and changed-key cases, Keychain denial, malformed/oversized/symlink certificates, interrupted publication, restart, existing/new TLS sessions, native expiry presentation, Android recovery text/Home and pinned TLS authentication/reconnect with an original pre-renewal pairing code. See issue #29 for exact executed results and installation outcome.

The macOS 15+ app uses native Swift certificate generation and memory-only Security identity import. Renewal replaces the Network listener after cancellation releases its endpoint, retaining already accepted connections. Python/OpenSSL remains a development reference peer; stable distribution remains a separate milestone. Renewal is explicit; unattended automatic renewal is not implemented.
